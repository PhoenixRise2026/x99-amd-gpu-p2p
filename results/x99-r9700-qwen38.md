# Real LLM TP=2 Benchmark: Stock SHM vs Direct P2P (Qwen3.8-27B-AWQ)

## Overview & Scope
This benchmark documents real-world LLM tensor-parallel inference (TP=2) running on dual AMD Radeon AI PRO R9700 GPUs across Intel Broadwell-EP Root Ports.

> [!IMPORTANT]
> **Scope Disclaimer**:
> These are case-study measurements demonstrating that real TP=2 LLM workloads actively utilize the direct P2P bus rather than falling back to host SHM staging.
> They are not intended as a generic dual-R9700 performance ceiling or guide.

---

## 1. Test Environment & Setup

* **Base Model Family**: Qwen3.8-27B (Dense DeltaNet + Attention hybrid architecture, 64 layers)
* **Tested Quantized Artifact**: `shawnw3i/Qwen3.8-27B-AWQ-MTP` (Safetensors INT4 AWQ)
* **Serving Framework**: SGLang v0.5.18
* **Tensor Parallelism**: `TP=2`
* **Attention Backend**: `triton` (`--attention-backend triton`)
* **Quantization**: AWQ 4-bit INT4 weights, group size 64
* **Hardware**:
  * CPU: Intel Xeon E5-2697A v4 @ 2.60GHz (Single-socket Broadwell-EP)
  * GPUs: 2x AMD Radeon AI PRO R9700 (32 GiB GDDR6 each, PCIe 3.0 x16)
  * Kernel: `6.8.12-r9700-p2p-dma44` (with `8086:6f00` P2PDMA whitelist entry)
  * IOMMU: Intel VT-d Translated (`DMA-FQ`)
  * ROCm: 7.2.4

---

## 2. A/B Comparison: Stock RCCL (SHM Fallback) vs Patched RCCL (Direct P2P)

### Test 1: Single Request Decode (193 input tokens, 512 output tokens)
| Metric | Stock (via SHM Staging) | Direct P2P (PCIe Host Bridge Direct) | Delta |
| :--- | :---: | :---: | :---: |
| **Decode Throughput** | 30.93 tok/s | **31.28 tok/s** | +1.13% |
| **Time Per Output Token (TPOT)** | 32.33 ms | **31.97 ms** | -0.36 ms |
| **Time to First Token (TTFT)** | 262.70 ms | **261.45 ms** | -1.25 ms |
| **End-to-End Latency** | 16.78 s | **16.60 s** | -0.18 s |

### Test 4: Concurrency Scaling Throughput
| Concurrency Level | Stock (tok/s) | Direct P2P (tok/s) | P2P TPOT |
| :---: | :---: | :---: | :---: |
| **C = 1** | 31.01 | **31.31** | 32.07 ms |
| **C = 2** | 37.61 | **37.90** | 52.41 ms |
| **C = 4** | 69.41 | **71.10** | 54.43 ms |

---

## 3. Analysis & Key Takeaway
1. **Bus Utilization Confirmed**:
   * Under stock RCCL, `isAllDirectP2p = 0` forced all TP=2 AllReduce collectives through CPU system memory buffers (`via SHM/direct/direct`).
   * Under patched RCCL, `isAllDirectP2p = 1` routed AllReduce directly across Root Ports through the host bridge (`via P2P/IPC`), reducing collective communication overhead and eliminating host memory bounce buffers.
2. **Compute Bound vs Bus Bound**:
   * Because single-request autoregressive decode is predominantly memory-bandwidth bound within each GPU (reading model weights from VRAM), collective communication accounts for a modest percentage of total token step time.
   * However, at higher concurrencies (C=4), communication overlap and reduced host memory traffic yield measurable throughput gains (69.41 -> 71.10 tok/s).
